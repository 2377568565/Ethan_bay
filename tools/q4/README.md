# 生成《预言的恩赐》网页用的程序

网站上的 HTML 都由这里的程序生成。换电脑、换会话都可以从这里一键重建。

## 一键重建
```sh
pip install fonttools brotli          # 需要 Python 3.8+
python3 tools/q4/fetch_assets.py      # 下载字体和圣经数据到 tools/q4/.work（约 220 MB，只需一次）
python3 tools/q4/render.py all        # 重新生成全部课程页、合集页和在线版（约 8 分钟）
```
- 下载来源都是公开的（Google Fonts、Noto、霞鹜文楷、thiagobodruk/bible、STEPBible），每个文件都核对 SHA-256，和建站时用的版本一致。
- 想把大文件放别处：设置环境变量 `Q4_WORK=目录`，下载和生成都用同一个。
- 生成结果是固定的：同样的输入两次生成的文件完全相同，所以 git 里只会出现真正改过的地方。
- 只改了网页的交互或样式时，可以用 `python3 tools/q4/_combined_only.py`，只重建合集页和在线版，快很多。
- 学课原文已从季刊 PDF 提取成 `pdf_blocks.json`，平时不需要 PDF。要从 PDF 重新提取：`Q4_PDF=季刊.pdf python3 tools/q4/extract.py --cache`。

## 主要文件
- `render.py`：总入口。
- `data/lNN.py`：每一课的解读内容与学课原文。
- `app.js`、`base.css`、`extra.css`：网页的交互与样式；`theme.css`：2026-10 的新设计（配色、首页、标签栏/侧栏、学课页导航、电脑版、投屏），接在前两个样式表后面，覆盖它们。
- `welcome.py`：欢迎页；`intro.py`：导言；`gen_yw.py` 与 `extract.py`：学课原文部分。
- `bible.py`：经文识别与弹窗数据；`build.py`：字体子集化；`online.py`：拆出在线版（`index.html` + `site/`）。
- `qa_data.py` 与 `qa/`：问题彩蛋的文章（网页与 PDF 共用），`qa/build.py` 生成 PDF。
- 问题彩蛋里内容特别多的专题可以单独做成一个网页：在 `qa_data.py` 里写 `url='xxx.html'`，卡片和学课里的入口就直接打开它（见下面“基督教两千年家谱”）。
- `zhlit/zhlit.json`：中文直译。
- `ask_core.js`：线上互动的共同规则（验签、防刷、谁能回复/删除/置顶），网页和 GitHub 同步任务共用；`render.py` 会把它放进网页。
- `ask_sync.js`：GitHub 同步任务运行的脚本。

## 专题网页：基督教两千年家谱（`history.html`）
```sh
python3 tools/q4/history.py           # 生成仓库根目录的 history.html（经文用 .work 里的和合本）
```
- `history_text.py`：各章正文；`history_data.py`：年表、教派名片、对照表、光谱、人物、常见问题、图表数字；`history_svg.py`：三张家谱图。
- 文字里的记号：`{{c:键}}` 资料出处（自动编号，点了能看出处）；`{{v:徒2:42}}` 整段经文；`{{ref:章}}` 跳到某一章。
- `history_sources.py`：每条资料的说明、网址和核对用的关键词。`python3 tools/q4/history_sources.py --check --facts` 会逐个打开网址，
  并把网页里和正文说法对应的原句打印出来，方便人工核对（大陆网络打不开的网站，可以放到 GitHub Actions 上跑）。
- `history_checked.py`：核对通过的网址（直接打开的，或用网页时光机存档核对的）。页面只用这里面的网址；新加的资料没核对过，生成时会提示。
- 怀爱伦著作等书籍按英文原著页码引用，没有网址。

## 首页的“新上架”弹窗（2026-10-25）
- 打开网站停在首页时，弹出最近 72 小时内上架或更新的问题彩蛋（按读者手机上的时间往前推 72 小时），点一篇直接在网站的浮层里打开。
- 数据：`qa_data.ITEMS` 每篇的 `at`（上架，北京时间）和可选的 `upd=(时间, 一句说明)`。`render.qa_new_html()` 把最新一次往前 10 天内的几篇写进首页作候选；`app.js`“新上架弹窗”在读者手机上筛出 72 小时内的，没有就不弹。
- 打开满 3 次才拿掉（2026-10-25 用户改）：`localStorage` 的 `q4:qnclk` 记下每篇 `{t: 上架或更新时间, n: 打开次数}`，进入这一篇（hashchange 到 `#qaN`）记一次；`n` 到 3 就不再列出，全部到 3 就不弹；30 天前的记录自动清掉。
- 样式：`theme.css` 的 `.qnew`（手机从底部升起，电脑在中间；只动 opacity / transform）。小羊在深色底上用 `lamb.dark_css('.qn-hd')`。

## 打开速度：GitHub Pages 的缓存
- 实测（2026-10-05）：每发布一次，所有文件的 `Last-Modified` 和 `ETag` 都换成发布时间，`Cache-Control: max-age=600`。
  所以每次推送（包括提问区同步）之后，读者的手机都得把文件重新下载一遍。
- 对策：正文字体（两个各约 400 KB）和经文数据（2.6 MB）下载一次就存进手机的 IndexedDB（`app.js` 的 `q4keep`，文件名带内容哈希，变了才重新下载；
  `online.py` 把这两个字体从样式表移到 `#wfonts`）；提问区同步只有访问人次变化时最多 4 小时保存一次（`ask_sync.js`）；平时尽量少推送、合并推送。

## 打开速度：正文和主程序拆出首页（2026-10-12）
- `online.py` 把 14 课（l0—l13）`<main>` 里的正文（约 1.2 MB）合成 `site/<哈希>.json`，把主程序（app.js 等，约 220 KB）存成 `site/<哈希>.js`，
  首页只剩骨架（压缩后约 90 KB，原来约 490 KB）。`<head>` 里的小脚本 `boot.js` 先从手机里（IndexedDB 库 `q4lz`）取这两份，没有才下载并存起来；
  网页读完后把正文放回各课的 `<main>`，再运行主程序，所以打开后的网页和原来完全一样（2026-10-12 逐字比对过）。
- 网站每次发布，读者只需重新下载骨架；正文、程序没改就不用重下。实测（100 KB/s、CPU 降速 4 倍）：更新后再次打开从约 6.2 秒降到约 2.3 秒；第一次打开不变（约 6.5 秒）。
- 下载失败会重试 3 次，还不行就在开场画面显示“点这里重新打开”。
- 生成后照旧 `git checkout -- site/` 留着旧文件：微信缓存的旧首页还会去找旧的 json/js。

## 账号（可选，用于跨设备同步）
不登录一切照旧。欢迎页左上角“账号”可以注册 / 登录（账号 + 密码，不需要手机号或邮箱）。
- 同步的内容：字号、夜间模式、朗读速度、称呼、手动选的地区；“写下我的回答”；“我们的行动”勾选；读到哪里；
  读完打卡（各设备合并）；本周研读时间（每台设备各记各的，欢迎页显示加起来的总数）；达到研读目标的周；
  以及身份（发过的问题、回复、打卡，管理员身份也跟着账号走）。
- 做法：账号名的哈希是账号编号；密码在本机用 PBKDF2 算出两把钥匙，一把加密（AES-GCM），一把给每项数据编格子号（HMAC）。
  注册时把这台设备的身份钥匙加密后存到账号里（消息 `u`）；之后每项数据加密后按格子存（消息 `w`，长的分段）。
  网上只有密文：账号列表在 `data/ask.json` 的 `accounts`，同步数据在 `data/vault.json`（平时打开网页的人不用下载它）。
- 忘记密码无法找回（谁也解不开密文）；密码至少 6 位，太常见的不让用。管理员请用不容易猜到的密码。
- 冲突处理：同一项两台设备都改了，以后改的为准；第一次在新设备登录时，以账号里的为准。

- 这一首下载完以后，先把它存进手机，再趁空把下一首也下载好，换歌时不用等。
- 听过的歌存在这台设备上（浏览器的 Cache Storage，最多 40 首，再多就删最久没听的），下次直接从手机里播，不用网络；
  列表里时长下面标“已缓存”。清单里已经没有的（比如换格式前的旧文件）会自动删掉。
- 开始“听朗读”时音乐自动暂停；开始放音乐时朗读停止。微信里不能直接下载，点下载会提示“在浏览器打开”。

### 批量加歌（文件很大也可以）
git 里单个文件不能超过 100 MB，网页上传不能超过 25 MB；GitHub Pages 整个网站不能超过 1 GB。所以原始文件不直接放进仓库：
0. 新的一批歌放进哪个文件夹：写在 `music/request.json` 的 `folder`（没有这个名字就新建一个，排在最后）；不写就放进“某年某月 新收录”。
1. 在仓库的 Releases 里新建一个发布（现在用的是标签 `Music`、名称 `Music_bay`），把歌曲文件拖进**说明框**：
   每首会变成一个链接，链接文字就是原来的文件名（中文也保留），单个文件最大 25 MB。
   - 也可以拖进说明框下面的附件区（单个最大 2 GB），但 GitHub 会删掉附件名里的中文，全中文名的文件还会因为“重名”传不上去；
     中文歌名请先压成 ZIP 再传到附件区（程序会自动解开，Windows 自带压缩用的 GBK/Big5 文件名也认得）。
2. 改 `music/request.json`（`release` 写发布的标签或名称，把 `rev` 加 1）并推送，`.github/workflows/music.yml` 就会运行 `music_import.py`：
   下载还没收过的文件 → 只取声音、统一音量 → 压成 48 kbps HE-AAC（`.m4a`，约 0.36 MB/分钟，听感接近 96 kbps 的 MP3）
   → 存成 `music/m<编号>.m4a` 并追加到 `list.json`。HE-AAC 要用完整版 fdk-aac（Ubuntu 自带的去掉了），`music.yml` 会从官方源码包现场编译；
   编译不成时自动改用 64 kbps 的 AAC-LC。`request.json` 里 `codec` 可选 heaac / aac / mp3，`reencode: true` 时把已收的歌从原始文件按新格式重压一遍。收过哪些文件记在 `music/sources.json`，以后再加新歌只收新的；
   同名、同长度的歌（同一首传了两次）不重复收。
3. 曲名用文件名（去掉“with lyrics”“Official Video”“歌词版”、开头的序号之类）；附件区的文件名不可靠时用歌曲标签。
   要改曲名、中文名（`sub`）、顺序，直接改 `list.json`。
- 本地也能用：`python3 tools/q4/music_import.py --dir 放歌的文件夹`（需要 ffmpeg）。
- 原样放上去：`--codec keep`（MP3 / M4A / OGG 不压缩）。OGG（Opus / Vorbis）在较旧的苹果手机上放不出来，所以另压一份 48 kbps HE-AAC，
  `list.json` 里记 `type`（如 `audio/ogg; codecs="opus"`）和 `alt`（备用文件），网页用 `canPlayType` 判断这台手机能不能放，放不了就改放 `alt`。
  现在《My Redeemer Is Faithful and True》就是这样放的（整理者上传的 Opus 138 kbps 原样，3.7 MB）。
- 格式对比试听页：`music-try.html`（整首歌：网页现在的 AAC / 原声 / 原声转 OGG〔Opus 约 70 kbps，2 MB 以内〕/ OGG 再转 AAC；文件在 `audio/music-try/`）。

## 打开速度（大陆网络连 GitHub 比较慢）
在线版 `index.html` 约 1.6 MB（压缩后约 430 KB），脚本在最后，整页下载完按钮才能用。为了不让人以为“卡了”：
- 开场画面：网页一开始下载就显示“预言的恩赐 · 正在打开，请稍候”和一条进度动画（只靠 HTML 和 CSS），6 秒后改成“网络有点慢，马上就好”；
  脚本就绪后（`html.ready`）淡出。脚本万一出错，25 秒后也会自己消失。
- 正文字体（两个各约 400 KB）不再抢先下载：首屏先用手机自带的字体，就绪 2.5 秒后（`html.wf`）才换上。
- 经文数据（2.6 MB）打开 10 秒后才在后台下载；在那之前点经文会先显示“加载中”再出来。
- 共享数据（问题、打卡、访问人次）：上次读到的存在手机里，打开就先显示，网上的最新数据到了再更新；不再等字体、图片下载完才去读。
- 测试：在 100 KB/s 的模拟网速下，原来空白 13 秒、约 15 秒才能用；现在 0.5 秒出现开场画面，约 6 秒欢迎页和数据都出来。

## 朗读录音（微信里也能听的自然人声）
微信内置浏览器没有“手机自带朗读”，而且自带的声音很机械，所以改为预先录好：
1. `python3 tools/q4/tts/speech.py`：从生成好的合集页取出每天原文、每段解读、问答文章，整理成朗读稿 `tts/script.json`

2. 改 `tts/request.json` 并推送，GitHub 上的 `.github/workflows/tts.yml` 就会用开源语音模型（CosyVoice3 / Kokoro，CPU 免费运行）

3. `render.py` 的 `TTS_VOICE` 指定网页用哪套声音；重新生成网页后，已录好的部分显示“🎧 听朗读”（微信里也能用）；
   没录的部分在支持的浏览器里仍用手机自带语音。
- 现在用的声音：D（Kokoro 女声 zf_001），录音在 `audio/kk-f/`：原文 92 天、解读 109 段、问答 2 篇，共约 14 小时、200 MB。

- 试听页：`tts-try.html`（五种声音读同一段，样本在 `audio/try/`；`tts/check.py` 可用语音识别比对检查读音）。
